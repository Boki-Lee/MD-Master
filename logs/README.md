# logs/ —— 参考库变更日志目录

> 本目录是本 skill 的**变更台账**。
> 目的：任何一次入库/改库都有带时间戳的白纸黑字，事后能查"谁在什么时候把什么改了"。

---

## 一、铁律（与顶层 `AGENTS.md` §6 一致）

**只要动了参考库，就必须写日志。** 具体两类：

| 触发 | 说明 |
|---|---|
| ① 归档入库 | 用户说"存入参考库 / 归档 / 存库"，走完 `ARCHIVE.md` 流程后写一条 |
| ② 用户直接让我改库 | 对库内任何文件/目录的新增、修改、删除、改名，改完写一条 |

不记录：在数据盘上新建的**项目**（`new_project.sh` 建的骨架）——那属于项目自身，不在库里。
但项目的**归档**结果要记。

> 例外：纯粹只读操作（看文件、grep、跑校验不改文件）不写日志。

---

## 二、文件清单

| 文件 | 作用 |
|---|---|
| `CHANGELOG.md` | 变更日志本体，**只增不改**，最新条目追加在文末 |
| `log_change.sh` | 追加一条带时间戳日志的辅助脚本（推荐用它，省得手写时间戳） |
| `README.md` | 本文件：规则说明 |

---

## 三、怎么写一条日志

### 方式 A：用脚本（推荐，时间戳自动生成）

```bash
bash logs/log_change.sh <类型> <摘要> [--files "文件1,文件2"] [--source "来源项目路径"] [--note "补充说明"]
```

- **类型**：`规则` / `归档` / `修改` / `删除` / `修复` 之一。
- **摘要**：一句话说清这次干了什么。
- **`--files`**：本次新增/修改/删除的文件（逗号分隔，相对库根目录）。
- **`--source`**：归档时填来源项目路径。
- **`--note`**：补充说明；也可以用管道喂正文：

```bash
# 归档一条
bash logs/log_change.sh 归档 "CNT1 收成 models/cnt_crown_v2" \
     --files "models/cnt_crown_v2/README.md,README.md,new_project.sh" \
     --source "/mnt/data2/lbj/CNT/CNT1" \
     --note "改 conf 相对路径；未收 dcd/coor/vel"

# 直接改库一条
echo "把 log_change.sh 的 --files 改成支持换行分隔" \
  | bash logs/log_change.sh 修改 "log_change.sh 增强" --files "logs/log_change.sh"
```

### 方式 B：手工追加到 `CHANGELOG.md`

照下面的格式，追加到**文末**：

```markdown
## 2025-10-08 21:30:00 +0800 — [修改] 一句话摘要

- **时间**：2025-10-08 21:30:00 +0800
- **类型**：修改
- **来源项目**：（归档时填，否则省略）
- **改动文件**：
  - `路径/文件`
- **说明**：
  具体改了什么、为什么改。
```

## 四、日志会覆盖到哪些动作（自检清单）

改动之前先在心里过一遍，收尾时逐条补齐：

- [ ] 新增/删除/改名了文件或目录
- [ ] 修改了脚本（`*.sh` / `*.tcl` / `*.py`）
- [ ] 修改了配置（`*.conf` / `*.par` / `*.prm`）
- [ ] 修改了文档（`README.md` / `AGENTS.md` / `ARCHIVE.md` / `WORKFLOW.md`）
- [ ] 改了规则本身（比如这次新增日志规则）—— **也要记一条**

> 时间戳统一用 `date '+%Y-%m-%d %H:%M:%S %z'`，即本机时区（+0800）。
